# (아래는 원본 초안 — 참고용)

> **v2 개정 요지**: 제품 순서를 뒤집었다. v0.1은 "구독 한도 트래커" 브라우저 확장(넓은 시장, 제작자 본인이 첫 사용자), v0.2는 기존에 설계한 "API 비용 가계부"(좁지만 지불력 높은 시장). 같은 제품의 두 얼굴이며, v0.1은 유입 깔때기, v0.2는 수익화 엔진이다.

## 0. 사용자 컨텍스트 (가장 중요)

- 나는 **비전공자**다. 모든 설명은 쉬운 한국어로 한다. 전문용어는 괄호로 한 줄 설명을 붙인다.
- 코드를 작성하기 전에 **무엇을 왜 하려는지 먼저 한국어로 설명하고 내 승인을 받는다.** 승인 없이 대규모 변경을 하지 않는다.
- 나는 Claude, ChatGPT, Genspark를 실제 구독 중이다. 즉 **내가 이 제품의 첫 사용자**다. 기능 판단이 갈리면 "내가 오늘 쓰고 싶은가?"를 기준으로 한다.
- 각 단계가 끝나면 "브라우저에서 이렇게 확인하세요"라는 검증 방법을 알려준다.

## 1. 제품 개요

**TokenLedger** — AI 구독을 여러 개 쓰는 사람을 위한 통합 사용량 대시보드.

- 한 줄 정의: "Claude, ChatGPT, Genspark… 내 AI 구독들의 남은 사용량을 한눈에."
- 핵심 페인포인트: 정액 요금은 내는데 **한도가 얼마나 남았는지는 막혀봐야 안다.** 도구가 늘수록 이 답답함은 곱해진다.
- 검증 근거: Claude 단일 도구용 한도 트래커(Usage for claude, onWatch, Claude Usage, AIQuotaBar, CodeQuota)가 여럿 존재하고 사용된다 = 수요 검증. 그러나 전부 단일 도구 전용이고 멀티 구독 통합은 공백 = 기회.
- 레딧 조사로 확인된 감정적 불만: "한 문장 답변에 사용량이 59%→100%", "루프 한 번에 하루 예산 소진", 월말·한도 도달 시점의 기습.

## 2. 제품 로드맵 (2단계 구조)

### v0.1 — 구독 한도 트래커 (브라우저 확장) ← 지금 만드는 것
- 타겟: AI 구독을 2개 이상 쓰는 모든 사람 (개발자 + 비개발자).
- 형태: Chrome 확장 (Manifest V3). 사용자가 이미 로그인한 브라우저 안에서 각 서비스 화면/로컬 데이터의 사용량 정보를 읽어 팝업 하나로 보여준다.
- 지원 대상 (우선순위 순):
  1. **Claude** — 가장 데이터 접근이 쉬움. 앱 내 사용량 표시 + (Claude Code 사용자의 경우) 로컬 JSONL. 기존 오픈소스(onWatch 등)의 접근법 참고.
  2. **ChatGPT** — 공식 "남은 한도 API" 없음. 웹앱 화면에 노출되는 한도 정보를 확장이 읽는다.
  3. **Genspark** — 크레딧 기반. 공식 API 제공 여부 먼저 조사 후 구현 방식 결정. (조사 전에 구현하지 말 것)

### v0.2 — API 비용 가계부 (기존 F1~F4)
- 타겟: API/Claude Code 헤비 유저. v0.1 사용자 중 전환.
- CLI 수집기 + 웹 대시보드 + 알림 + 낭비 감지. 상세 명세는 6장 참고.

## 3. 기술 스택

| 구성요소 | 기술 | 비고 |
|---|---|---|
| v0.1 확장 | TypeScript + Manifest V3, 팝업 UI는 React | Chrome 우선, Edge는 무료 보너스 |
| 데이터 저장 | 확장 로컬 스토리지(chrome.storage) | v0.1은 서버 없음 = 운영비 0 |
| v0.2 수집기 | TypeScript CLI (npm) | ccusage 구조 참고 |
| v0.2 대시보드 | Next.js + Supabase | |
| 결제 | Stripe 또는 Lemon Squeezy | v0.2에서 도입 |

## 4. 핵심 설계 원칙 (절대 위반 금지)

- **프라이버시 우선**: 대화 내용·프롬프트·계정 정보는 절대 수집하지 않는다. 읽는 것은 사용량 수치·한도·리셋 시각뿐이다. v0.1은 아예 서버가 없다 — 모든 데이터는 사용자 브라우저 안에만 있다. 이것을 마케팅 1번 문구로 쓴다.
- **읽기 전용**: 사용자를 대신해 클릭·전송·요청하지 않는다. 화면과 로컬 데이터를 읽기만 한다.
- **로그인 대행 금지**: 사용자의 아이디/비밀번호를 받지 않는다. 이미 로그인된 브라우저 세션 안에서만 동작한다.
- **단순함 유지**: 1인이 운영 가능한 범위를 넘는 기능은 만들지 않는다.

## 5. v0.1 기능 명세

### E1. 통합 팝업 대시보드
- 툴바 아이콘 클릭 → 팝업 하나에 서비스별 카드: 남은 사용량(%), 한도 리셋까지 남은 시간, 마지막 갱신 시각.
- 데이터를 못 읽은 서비스는 숨기지 말고 "확인 불가 + 이유"를 표시한다 (조용한 실패 금지).

### E2. 한도 임박 알림
- 서비스별 임계치(기본 80%) 도달 시 브라우저 알림.
- "리셋 완료" 알림 (한도가 풀렸을 때) — 사용자가 가장 반가워할 순간.

### E3. 배지 표시
- 툴바 아이콘 위에 가장 임박한 서비스의 남은 % 를 배지로 상시 표시.

### E4. 간단 히스토리 (로컬)
- 최근 7일 사용 추이 미니 차트. 로컬 저장만.

v0.1에서 만들지 않는 것: 계정/로그인, 서버 동기화, 결제, API 비용 분석(전부 v0.2).

## 6. v0.2 기능 명세 (기존 설계 보존)

### F1. 통합 수집기
- `npx tokenledger init` 한 줄 설치. 대상: Claude Code(JSONL), OpenAI(usage API), OpenRouter(API). Cursor는 비공식 API 리스크로 연기.

### F2. 드릴다운 대시보드
- 일/주/월 → 도구별 → 프로젝트별 → 세션별. 입력/출력/캐시 토큰 분해.

### F3. 사전 알림
- 일일 예산 80%/100%, 급증 감지(7일 평균 대비 3배), 주간 리포트. 이메일 + Discord/Slack 웹훅.

### F4. 낭비 감지 (차별화 핵심)
| 신호 | 감지 로직 |
|---|---|
| 루프 의심 | 유사 도구 호출의 단기간 반복 (시그니처 해싱) |
| 실패 재시도 체인 | 에러 직후 재호출 연쇄 |
| 컨텍스트 비대 | 입력:출력 비율 이상치 + 캐시 히트율 급락 |
| 무산출 고비용 | 코드 변경 0줄 + 비용 상위 10% 세션 |
- 구현 순서: 무산출 고비용 → 실패 재시도 → 컨텍스트 비대 → 루프 의심.

## 7. 만들지 않는 것 (스코프 방어)

- 프록시/게이트웨이 (요청 경로 개입 금지)
- 로그인 대행, 계정 정보 수집
- 예산 초과 강제 차단
- 팀 권한 관리, 엔터프라이즈 기능
- 프롬프트 최적화 제안

누군가(미래의 나 포함) 이 목록의 기능을 요청하면, 먼저 이 섹션을 상기시킨다.

## 8. 알려진 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 각 서비스 UI 변경 시 확장이 깨짐 | 서비스별 파서를 모듈로 분리해 하나가 깨져도 나머지는 동작. E1의 "확인 불가" 표시로 우아하게 실패. 빠른 패치가 곧 경쟁력. |
| 서비스 약관 이슈 | 읽기 전용 + 로컬 전용 + 자동화 없음으로 리스크 최소화. 각 서비스 파서 구현 전에 해당 서비스 약관의 관련 조항을 확인하고 나에게 보고. |

## 9. 작업 규칙

1. **조사 → 보고 → 승인 → 구현** 순서를 지킨다. 코드부터 쓰지 않는다.
2. 한 세션에서는 한 기능만 다룬다.
3. 기능 완료 시마다: 테스트 실행 → 통과 확인 → git 커밋 (메시지는 Claude가 작성).
4. 같은 에러로 2~3회 실패하면 재시도를 멈추고, 시도한 방법과 실패 이유를 정리한 뒤 다른 접근법 2가지를 제안한다.
5. 외부 서비스 작업 시 "사용자가 직접 할 일"과 "Claude가 할 일"을 구분해 안내한다.
6. 새 라이브러리 추가 전에 이유와 대안을 설명하고 승인받는다.
7. 각 서비스의 사용량 데이터 획득 방법은 **구현 전에 반드시 조사 단계를 거친다** (특히 Genspark).
